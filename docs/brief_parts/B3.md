# Brief part — B3 UI / PWA (session B3.1)

**What it is.** A React + TypeScript PWA that only renders what the server decides:
- Tiers, owners, states, closure and every open count come from the API.
- Permissions only hide controls.
- Wire types, enum lists, routes, reason codes and the permission matrix are imported from the generated contract files.

The glance strip leads with one sentence, e.g. "Closure blocked: 3 Tier 1 items with Dr Lim", then per-tier counts, the top three questions and the latest decisions. The timeline is a patient `git log` with diff chips. Flag cards cite quoted spans, with decisions in a bottom sheet on phones and a side panel on workstations. The source viewer highlights verified spans and shows cited and current versions side by side.

**Honesty rules in the UI:**
- A 501 renders "not available in this build", never a stand-in.
- A span whose converted slice does not equal its `quote` is not highlighted.
- Tier is always a text label plus a distinct shape.
- Absence reads "Not documented in the supplied sources".

**Adding sources.** Clinicians paste a note or upload a PDF.
- Corrections become new versions beside the original, with metadata locked.
- Retries are idempotent.
- Scanned or timed-out PDFs are kept and labelled, never read as complete.

A real bug surfaced while verifying this against the real engine. The run control's default cutoff (floored to the minute) excluded a note recorded seconds earlier, because a version counts only if recorded at or before the cutoff, and the server refuses future cutoffs. The default is now the latest recording time rounded up to the second. The test asserts that property rather than a format.

**Governance states.** While the rule set is not approved (B4's approval check), rule-dependent views say plainly that checks are paused for clinical governance approval. They are never shown as a server outage and never filled with old results.

**Feedback and governance views.** After deciding a flag, a clinician can say whether it was useful, or name the right owner. The answer, plus a time on screen that is measured and never invented, goes to offline governance review and never changes the flag. Governance roles see an aggregate page: counts by rule, tier, status and age exactly as served, with small counts shown as "<5". There are no totals (sums could reveal suppressed cells) and no patient or encounter details.

**Storage and caching.**
- The workspace token lives only in JS module memory.
- Nothing is written to localStorage, sessionStorage, IndexedDB or cookies from JS.
- The hand-written service worker precaches the static shell only, never intercepts `/api/`, and has no runtime caching.
- Offline, the shell says "Offline — clinical content is not stored on this device."

**Measured (23 Sep 2026, this container, Chromium 141; Node 22.22.2, 24.21.0 and 26.9.0):**
- Vitest: 30 cases in about 9 s, green on Node 22 and 26 (24 checked in B3.1).
  - 117 golden evidence spans convert from code points to UTF-16 and equal their quote. This includes the 16:00 span after an astral emoji, where naive slicing is off by one.
  - An outage keeps the last results labelled with their generation time, while a 403 removes them.
- Mutation spot-checks: 36/36 caught, plus 1 on the pytest wrapper.
- Real-browser walk against the integrated API (real engine and approved rule set since CP2), at 375×812 and 1440×900: 12/12 pass in about 46 s, with real diff chips and post-decision glance and summary, including feedback (B2) and the aggregate page (B4) on real routes, intake of both fixture PDFs through B2's real PDF path. It covers:
  - sign-in, the 11:30 and 16:00 runs, the superseded Tier 1;
  - cited v1 beside current v2, the emoji-offset highlight;
  - an accept decision, closure blocked, refusal for a non-member;
  - a PDF opened through the single-use `no-store` document token (reuse refused), the scanned PDF's explicit no-text state;
  - clipboard copy, the print layout, Chromium installability checks and the offline shell.
- After the path: browser storage is empty, and the SW cache holds shell paths only.
- axe-core: 0 WCAG A/AA violations in 14 screen states after two fixes.
- Production bundle: about 283 kB JS (87 kB gzip), 16 kB CSS, plus fonts.

**Known gaps:**
- No feedback (usefulness) UI.
- No aggregate page.
- Only the accept decision is executed end to end; the other decision paths are inspected.
- The carried-forward chip opens the later note only, not the origin beside it.
- No focus trap in the mobile sheet.
- Edge and Safari are not run (unavailable in the build container).
- Running the UI is B5's README step.
