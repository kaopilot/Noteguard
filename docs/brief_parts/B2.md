# B2 brief part — access enforcement, audit, intake, redaction

**Access enforcement (two layers, two data paths).**
- Every encounter-scoped route passes a guard that checks care-team membership and role against a directory built at startup.
- Every store method re-checks scope, role and, for decisions, the exact tier/owner rule against the workspace's own copy.
- Out of scope returns 404, never 403, so nothing reveals that an encounter exists; in scope with the wrong role returns 403.
- Fault injection (executed): with the route guard removed, all 17 encounter-scoped store methods still refuse three out-of-scope users (a clinician on no team, a clinic admin, a medical director), and a forged context pointing at another user's workspace is refused. Over HTTP with the guard removed, a nurse still cannot dismiss a Tier 1 flag.
- Sessions are random server-side tokens in an HttpOnly, SameSite=Lax cookie. Workspaces are per page load, keyed by the hash of a token held only in JS memory.

**Audit and provenance are separate.** The audit stream is append-only and hash-chained, and every field is allowlisted (ids, enums, hashes, timestamps). A test verifies the chain and detects a dropped or edited event. Provenance lives on the flags (Evidence → immutable SourceVersion + span). Logs are one JSON logger through the contract allowlist; the uvicorn access log is off, and requests are logged by route template only.

**Marker test (executed).** Markers were placed in the body, header, query string, path, cookie, a malformed request, a login, a decision rationale and a PDF text layer, title and filename. None reached a log record, stdout/stderr, an error body or an audit event. The PDF marker was confirmed to pass through extraction. The same check against a real uvicorn server found 0 marker occurrences and no access-log lines. An unexpected exception ends as a bare 500 with no traceback in any log.

**Intake.**
- Every version is immutable and carries a SHA-256 and an idempotency key.
- PDFs are refused above 10 MB, above 50 pages, or without PDF magic bytes, and extraction has a 10 s timeout.
- Scanned, partial, unparseable and timed-out PDFs are retained and labelled, never "complete".
- Extraction reproduces the pinned pdfplumber output for both fixture PDFs (executed).

**Redaction (risk reduction, not permission).**
- Deterministic patterns: NRIC/FIN, SG phone, email, MRN (ported from care-core, MIT), plus roster names, honorific names, postal codes and dates of birth.
- A code-point offset map back to the original; the original is never modified.
- Fail closed: an unrecognised 7+ digit run blocks egress.
- On a **self-written** 10-item labelled set: 1 of 19 identifiers not redacted (lower-case "dr lim"), 1 of 19 clinical strings over-redacted ("Nurse Led Clinic"). This is not independent evidence.

**Concurrency (executed):** in 20 trials of 6 simultaneous decisions on one flag, exactly one succeeded each time and the rest got 409 with the current revision, so no decision was lost.

**Measured** (this container, `time.perf_counter`):
- Check-run via the API with the stub engine, including login and workspace creation: median 9.1 ms, max 60 ms (n=30).
- PDF extraction: 0.6 ms median for the 22 KB image-only scan, 4.8 ms for the 0.9 KB text PDF (n=10).
- Seam preview (scratch, not a test): the real B1 engine behind this API took 17 ms for the 11:30 run.

**Demonstrator vs production (gaps).**
- Single-process, in-memory store; production uses Postgres + RLS.
- Local HTTP (`secure=False` cookie).
- The PDF size limit applies after the body is received.
- No malware scan, no OCR, no rate limiting.
- Timed-out extraction threads are not killed.
- The audit chain is not externally anchored.
