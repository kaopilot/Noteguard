# Brief part — B4 Governance and the AI line (measured, 23 Sep 2026, commit on b4-governance)

**Nothing learns online.** Feedback is recorded content-free (B2) and read only by offline tools. The runtime loads a ruleset only if `rulesets/APPROVAL_<v>.md` is approved, cites an evaluation report, and its hashes equal the files, re-checked on every load; otherwise check runs return 503 `ruleset_unapproved`. v1 is a draft today (refused: `not_approved` only); @k approves at CP2. Rollback = re-pin the previous approved version. `propose.py` refuses any proposal that lowers, disables, narrows, retires or re-thresholds a protected rule (Tier 1, allergy, medication, critical-result, PDF), and any synonym on a cue that can suppress flags.

**Release gate (measured).** `evaluate.py` runs the real engine over 23 gated cases: 18 hand-labelled by B4 from the rule catalog, committed before the engine ran, fictional roster; plus 5 golden scenarios. v1 vs v1: **Tier 1 recall 17/17**, gate passed, report sha256 `81cc969e…`. On the B4 cases every labelled flag was raised (14/14). The one disagreement is a declared precision probe: CRIT-001 precision 4/5, where a response written as "hyperkalaemia managed" is outside the registry, so the flag stays (conservative). A declared known-limit case (allergen outside the registry) is not recognised and is kept out of the gate. The gate refuses a candidate that disables CRIT-001, lowers ALG-001 to Tier 2, extends a negation cue, or (with the ruleset unchanged) whose engine drops CRIT-001. One evaluation (both sides, 24 cases) took 0.10 s (single `perf_counter` run in the build container). Limits: the B4 cases use registry vocabulary, so they measure generalisation across roster and wording, not paraphrase; the golden cases are not independent (the engine was built against them).

**Aggregate view.** Counts by rule, tier, state and age bucket; no text, no identifiers; counts below 5 shown as "<5". Aggregate roles only, checked at the route and again at the store. Gaps: no complementary suppression; owner response time awaits CCR-04.

**AI line.** AI drafting is off by default and the app is fully functional without it. When enabled it may only draft an explanation of one existing flag, from its hash-verified quotes, sent only as redacted `QualifiedRedactedText`. Output is discarded (rule text shown) on any extra field (so no tier/owner/state), missing or unknown evidence id, registry entity or dose absent from the cited quotes, certainty above the source, unsupported negation, or forbidden phrase; timeout (3 s default) or provider error shows "AI drafting unavailable; showing rule explanation"; a breaker stops calls after repeated failures. No route calls it yet. Limit: entity checks only know registry terms.
