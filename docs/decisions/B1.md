# B1 decisions (append-only)

Session B1.1 (22 Sep 2026). Each line: decision — reason. Nothing here changes a contract; CCR-01 is the only proposal.

1. 2026-09-22 — Engine layout: `registry` (compiled from the bundle), `normalise` (offset map), `extract`, `diff`, `rules/` (one pure function per rule), `flags` (orchestration), `bubbles`, `summary`, `engine` (EngineAPI) — keeps each check independently testable (8.1).
2. 2026-09-22 — Negation/uncertainty scope: a registry cue scopes forward over the rest of its clause (split on `,` `;`), ≤ 6 tokens, never across `:`; a `?` not touching a following word makes its clause uncertain — found by probe: "No change: amlodipine 10 mg" would otherwise hide a dose discrepancy.
3. 2026-09-22 — An allergen counts as a named allergy only within 3 tokens of an allergy keyword in the same clause — limits "allergy check before penicillin given" style false Tier 1s without a grammar.
4. 2026-09-22 — A queried named allergy ("?penicillin allergy") is the counter side of ALG-001; a queried or unrecognised denial ("allergies: nil?") is `review_required` and never a claim — a possible allergy against a denial needs a clinician (conservative); 8.1 forbids reading an unclear denial as NKDA.
5. 2026-09-22 — CRIT-001: a later response statement repeating an earlier critical value of the same analyte ("K 6.4 reviewed") refers to it and is not a new observation; a response in the SAME statement or source as the first value does not count (8.5 requires a later source_time) — required by the 16:00 golden and by 8.5 read strictly; the false-positive pattern is listed in RULES.md.
6. 2026-09-22 — A queried critical value ("?6.5") stays critical and is `review_required`; a value with a non-registry unit is `review_required` and not critical — found by probe: the "?" made the value unparsed and CRIT-001 silently absent (L4 applied to observations).
7. 2026-09-22 — DOSE-001 compares within epochs split by explicit changes; a missing frequency is "not stated", not different; a flag needs regimens from ≥ 2 sources ("across sources", 8.2).
8. 2026-09-22 — Explicit change (L3) = registry change cue in the drug's clause, source discipline clinician or pharmacy, source_time strictly later than the previous assertion — "unambiguous order"; the same words from a nurse or at the same time stay a conflict.
9. 2026-09-22 — PEND-001 associates subject and pending cue at statement level; a "linked later statement" is any later statement (any source) naming the same subject; owner and timing may come from different linked statements — matches the linked case in `test_pending_owner_and_time`; known false-positive pattern in RULES.md.
10. 2026-09-22 — DIFF-001 looks for deterioration markers between the ORIGIN and the repeat, using only `deterioration_*` thresholds (not critical values) — @k's SpO2/RR decision; origin-based is the more conservative reading.
11. 2026-09-22 — Near-verbatim = difflib token ratio ≥ 0.9 with identical numbers, registry terms and negated terms — a changed value or a dropped "not" is never "the same text".
12. 2026-09-22 — Rerun evidence matching key = (source_id, role, normalised facts of the cited statement for the rule's fact types); cited evidence is never dropped; reason text is kept unless new evidence arrives — implements README convention 7 without re-anchoring citations.
13. 2026-09-22 — A human-resolved/dismissed flag reopens only for new evidence from a source not already cited; a resolve naming the correct entry (adjudicated_evidence) makes the other side's statements inactive for THAT flag only — L2 (restating the winner never reopens) and feedback P7.
14. 2026-09-22 — An active flag whose finding is answered or no longer found becomes SUPERSEDED (evidence kept); a superseded flag found again is REOPENED; `new_evidence_since_decision` is set only when reopening a human decision. Assumes cutoffs only move forward (the API reruns at the latest cutoff).
15. 2026-09-22 — Existing flags keep owner, tier, created_at, first_run_id and ready_for_clinician; `last_run_id` and `check_version` follow the current run; flags of rules disabled in the current ruleset are returned unchanged.
16. 2026-09-22 — `Flag.question` is set only for DIFF-001 (differencing review question) — the goldens compare "has question" and set it only there.
17. 2026-09-22 — Bubble absence search: every registry term named (not negated) AND, if cues are listed, one live cue; response searches over a critical observation use exactly the CRIT-001 suppressor test; flag-rule searches start at the trigger statement — README convention 8.
18. 2026-09-22 — Bubble uncertainty notes are engine text keyed by rule (the QuestionTemplate schema has no field for them); linted by B0's forbidden-phrase test.
19. 2026-09-22 — `Summary.stale_after_source_change` is False at generation; only the caller can see sources that arrive later.
20. 2026-09-22 — Assertion and change ids are content hashes via `contracts.ids.sha256_hex` (`asr_`/`chg_` + 24 hex), not `new_id()` — a pure engine must give identical output for identical input (verified on all five scenarios).
21. 2026-09-22 — Display time uses a fixed UTC+8 offset — Singapore has no DST, and a tz database read would be file access inside the engine.
22. 2026-09-22 — Unit arithmetic lives in `engine/units.py` until CCR-01 lands; recognition of units stays in the registry.
23. 2026-09-22 — No dependency added (difflib, unicodedata, re are stdlib). `rulesets/v1.json` and `registry_v1.json` unchanged, so the approval hash is unaffected.
24. 2026-09-22 — Own test changed (stricter, not looser): `test_adjudication_converges` gains the "restate the winning side from a different source → no reopen" step required by L2 — the original test could not fail when adjudication was ignored (mutation spot-check). New B1 test file `tests/engine/test_engine_edges.py` (13 edges + one variant encounter), labelled a regression guard, not independent evidence.
25. 2026-09-22 — Lane commits use the local identity "B1 engine (AI chat) <b1-engine@noteguard.invalid>", mirroring B0's.
