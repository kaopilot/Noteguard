# B3 decisions (append-only; newest last)

## Session B3.1 — 23 Sep 2026
1. **Built against B2's real API, not the B0 stub.** The bundle's `main` is after the B2 merge (not `cp0`). The API is real; the engine behind it is the stub. Consequences shown in the UI rather than hidden:
   - The stub engine emits no `changes`, so the timeline says "This check run reported no changes between sources".
   - After any decision, bubbles, glance and summary answer 501 and render "… is not available in this build".
2. **Dependencies** (lockfile `frontend/package-lock.json`, exact pins):
   - Runtime:
     - react / react-dom 19.3.0 (MIT).
     - @fontsource/atkinson-hyperlegible 5.3.0 (OFL-1.1): self-hosted, so the app makes no third-party font requests.
   - Dev:
     - vite 7.3.6 (MIT), @vitejs/plugin-react 5.2.0 (MIT), typescript 5.9.3 (Apache-2.0).
     - vitest 3.2.7 (MIT), jsdom 26.1.0 (MIT).
     - @testing-library/react 16.3.3 and @testing-library/dom 10.4.2 (MIT).
     - @types/react, @types/react-dom 19.3.0 and @types/node 22.20.4 (MIT).
     - @playwright/test 1.56.0 (Apache-2.0).
3. **Known dev-only advisory: GHSA-82fw-gwwq-j7x9 (moderate) in vitest ≤ 4.1.10.** It is a path traversal via `vi.mock` redirect, reachable only when running untrusted test code; none of our tests use mock redirects.
   - Why not upgraded: vitest 4.1.11 would not install (npm arborist `edgesOut` error on jsdom's optional `canvas` peer).
   - Proposal: retry vitest ≥ 4.1.11 (the patched range per `npm audit`) after CP1.
4. **Demonstrator login picker** reads the synthetic roster from `fixtures/encounters/clinic.json` at build time. It holds names and roles only, nothing clinical; production identity is SSO/SMART.
5. **Unit tests live in `frontend/tests/`, outside `frontend/src`.** The seam scanner's per-line vocabulary check targets product source; tests legitimately name wire values.
   - The API double (`tests/fakeApi.ts`) is built from the golden fixtures and the contract route templates.
   - It picks the golden by (cutoff, prior scenario), so 11:30 then 16:00 serves `ENC-A1_1600_rerun`, matching the real API.
6. **"Decided" flags sit behind the history toggle**, derived from contract data rather than a hand-written state list: a state is decided when `CONTRACT.decisions.transitions` offers no move from it.
   - Every open or blocking count on screen is a server number (glance, closure view); the UI does no arithmetic on flag states.
7. **`! contradicts` chips** come from contradiction-lens flags' evidence, because `ChangeKind` has no "contradicts" value. Everything else in the chips is the run's `changes`.
8. **Display wording** uses `Record<WireType, string>` maps (labels.ts), so TypeScript fails the build if the contract adds a value. The maps choose words only.
9. **Permissions are hide-only.** Offered actions come from `CONTRACT.permissions` (role × tier × relation) plus `CONTRACT.decisions.transitions`. Relations are derived client-side for hiding only; the server re-checks at the route and store layers, and the UI shows its 403 text.
10. **Service worker is hand-written** (public/sw.js):
    - Precaches only the explicit build list (hashed assets, offline page, manifest, icons) injected by a 20-line Vite plugin.
    - No runtime caching at all (no `cache.put`).
    - `/api/`, non-GET and cross-origin requests are not intercepted.
    - Navigations are network-first, falling back to `offline.html`.
    - Registered only in production builds.
11. **A span whose converted slice does not equal `quote` is not highlighted;** the viewer says so. Showing the wrong words is worse than none.
12. **`StaleRevision` (409 body) is missing from the generated types.** It is read through a local structural type with optional fields typed by generated enums; CCR-03 is proposed.
13. **Closure "Check closure now" on 200** says no Tier 1 blocks closure and that closing in the EMR remains the clinician's action. Nothing is written back.
14. **The Playwright walk (`npm run e2e`) is not part of `make test`,** because it needs a browser and two servers.
    - `NG_CHROMIUM` only selects a local browser binary; it is not a security switch, so L12 is not engaged.
    - Its results are recorded in the handoff.
15. **`tests/ui/test_ui_placeholders.py` is replaced by `tests/ui/test_ui_frontend.py`:**
    - One Vitest run per session with the JSON reporter.
    - Each owned check asserts its named cases ran and passed.
    - Vitest failure text is not echoed, because it can contain synthetic note text.
16. **Design changes after screenshot review:**
    - Tier icons became octagon-with-bar / triangle / hollow ring, because octagon and filled circle were indistinguishable at 16 px.
    - Mobile app bar made static and one row.
    - Run control collapses behind "Run checks again" after the first run.
    - Sheet animation no longer fades opacity.
17. **Mutation spot-checks (12.1), all applied and all caught** (then reverted):
    - offsets: code points used as UTF-16 indices → 3/3 offset cases fail.
    - sw: `/api/` guard removed → 1 fails (the /api/ navigation case).
    - sw: runtime `cache.put` added → 1 fails.
    - storage: token copied to sessionStorage → main-path case fails.
    - tier: text label removed → 2/2 fail.
    - tier: two tiers share a shape → 1 fails.
    - html: `dangerouslySetInnerHTML` added → static case fails.
    - decision: 409 treated as success → stale case fails.
    - pytest wrapper: a Vitest case renamed → `test_tier_labels_not_colour_only` fails ("did not run").

### Pre-handoff review against card B3, Sections 8.7–8.9, 9, 10.2 and 13, and the Review Standard (same session)
18. **Outage retention (Review Standard S09-R01/R03).**
    - When a refresh returns 5xx or no network, the last good results stay on screen. They sit under a banner naming the failure, the run's completion time and its cutoff, with "Try again" and a 30 s auto-retry.
    - A 4xx (e.g. 403) is **not** treated as an outage and replaces the old results, because access may have been withdrawn.
    - Tested both ways.
19. **Inline decisions on wide screens.** Card B3 and §13 say "inline decisions (bottom sheet on mobile)". The form now renders inside the flag card at ≥ 1100 px and as a bottom sheet below that. Both variants are a `form` named "Decide: <title>".
20. **Bug found in review:** on wide screens, "Show in source" from the Questions or Closure tab set the target but the source pane only exists on Review, so nothing appeared. `openSource` now switches to Review on wide screens. Tested.
21. **S16-R05:** a 404 on a cited version's text now shows "This source version is no longer available…". Previously it showed the misleading "no check run yet".
22. **Exact spec wording:** "AI drafting disabled" (§9, L10) and "Stale: sources changed after cutoff" (§8.9). Closure blockers also get a "Show evidence" link (§8.9 "evidence link").
23. **Accessibility scan (axe-core 4.13.0, run from /tmp, not a repo dependency):** 7 states × 375 px and 1440 px, WCAG 2 A/AA + best practice.
    - Two findings, both fixed: the sheet `<header>` was a second banner landmark (now a `div`), and horizontally scrolling tables were not keyboard-focusable (now focusable, labelled regions).
    - After the fixes: 0 violations in all 14 states.
    - Proposal: add axe-core (MPL-2.0) as a dev dependency so this becomes a repeatable e2e check.
24. **Installability** is checked through Chromium's `Page.getInstallabilityErrors`. The single `in-incognito` error is excluded because Playwright contexts are incognito-like. The manifest also parses with 0 errors.
25. **Mutation spot-checks, round 2, all applied and all caught** (then reverted):
    - outage data dropped;
    - 4xx treated as an outage (this mutation survived at first; the 403 case was then added and now catches it);
    - missing-version text removed;
    - inline slot not rendered;
    - Review tab not switched.
26. **Not in B3's power:**
    - `make run` starts only the API, and nothing serves `frontend/`, so a reviewer needs `cd frontend && npm run dev` (Vite proxies `/api` to :8000). Proposal to @k: a `make ui` target, or a `run` that starts both.
    - Review Standard R12 lists Chrome, Safari and Edge. Only Chromium 141 is executed here: Playwright's browser CDN is not on this container's allow-list, so no WebKit. Edge shares the Chromium engine; Safari is untested.
