4. 2026-09-23 — Session = random token (server-side table, `session_ttl_s`), cookie HttpOnly, SameSite=Lax, Path=/api, `secure=False` (local HTTP is a declared gap). Logout revokes server-side. The B0 stub's staff-id cookie is forgeable and is gone.
5. 2026-09-23 — `WorkspaceInfo.encounter_ids` lists only encounters the user may read (the stub listed all: existence leak).
6. 2026-09-23 — Workspaces keyed by sha256(token); only `workspace_hash` is logged. Expiry returns 410 and drops the clinical content; a token owned by someone else returns 401 `workspace_required`.
7. 2026-09-23 — Reset follows the frozen matrix (`RESET_WORKSPACE` needs care-team membership), so a clinic admin gets 403 resetting their own empty workspace. Harmless (TTL expiry still applies); flagged in case @k wants reset to be owner-only.
8. 2026-09-23 — New intake gets `version_time = received_at =` server clock (no backdating). Golden-day cutoffs therefore exclude newly added notes; a run at "now" includes them.
9. 2026-09-23 — Replay and idempotency: with no `external_id`, the logical document id is a hash of (source type, title, discipline, author, source_time, content sha), so an identical re-post is a 200 replay and a different author or time is a new document. A client key reused with different content returns 409. A new version needs `source_id` (or namespace + external_id) and identical Source metadata; namespace is compared only if sent. The author must be an active care-team member (422 otherwise).
10. 2026-09-23 — PDF intake reproduces the pinned pdfplumber contract (executed against both fixture PDFs); "negligible text" means char_count == 0, as pinned.
    - An unparseable PDF is retained with status `failed` (201).
    - A timeout is retained as `failed` and returns 422 `pdf_extraction_timeout`.
    - Too large, not a PDF, or too many pages are refused and not retained.
    - Gaps: limits are checked after the body is received; a timed-out extraction thread keeps running.
11. 2026-09-23 — A check-run cutoff must not move backwards (B1 #14 assumes it) or lie in the future; both return 422 `validation_failed`.
12. 2026-09-23 — Engine-result guard: the API refuses to commit a run (500 `internal_error`, nothing stored) if the engine moves a flag into a human-only state, drops a known flag, or returns a flag id that is not this encounter's. This is defence in depth for "no Tier 1 closes automatically", not rule logic.
13. 2026-09-23 — Bubbles, summary and glance are recomputed through the engine from the current flag states and decisions on every read. With the stub engine, any read after a decision is 501 `not_implemented` (explicit), never a stale golden. Closure and the flag list come from the store plus `contracts.states` and keep working.
14. 2026-09-23 — Closure blocker order is (created_at, flag_id). The goldens' blocker order is hand-declared (the materializer checks it only as a set), so B2's golden test compares the blocker lists as sets. I1 should do the same.
15. 2026-09-23 — POST closure (responsible clinician) is also blocked when:
    - no check has run;
    - sources changed since the last run;
    - the run's cutoff does not cover every source version.
    Closure is recorded only in the audit stream; the contract has no "closed" field.
16. 2026-09-23 — Decision field rules:
    - Fields that do not belong to the action are refused (422 `validation_failed`).
    - A reason code on accept, edit or reassign returns `reason_code_not_allowed`.
    - A resolve reason must also be in `RESOLVE_REASONS_BY_RULE`.
    - Adjudication references must match the flag's evidence spans.
    - A reassign or edit-owner target must be an active member with `REASSIGN_TARGET_ROLES[tier]` and must differ from the current owner.
    - `duplicate_of` needs another flag in the encounter.
    - `tier1_cannot_be_deferred` is unused: there is no defer action.
17. 2026-09-23 — A JSON list on the decision route returns 422 `bulk_not_supported`, detected from the validation error type without echoing the input.
18. 2026-09-23 — Feedback:
